## 用户画像

用户是一位多角色、多领域的专业人士：

| 角色 | 描述 | 服务状态 |
|------|------|---------|
| **正职工作** | 网易美术经理，管理约10人团队 | ⚠️ 部分服务 |
| **AI 开发爱好** | 使用 AI 辅助编程，开发个人软件 | ⏳ 规划中 |
| **投资理财** | 有自己的风控系统（RiskControl），关注投资决策 | ⏳ 规划中 |
| **创业项目** | 正在开发 3D AI 生成系统 | ⏳ 规划中 |
| **家庭生活** | 有妻子、2岁女儿、五六十岁父母需要照顾 | ⏳ 规划中 |

### 使用设备
- Mac 电脑（主力开发）
- PC 电脑（部分开发工作）
- iPhone（移动端）
- 使用 iCloud 存储文件

## 开源参考项目

### 🧠 AI 知识库与记忆

#### Khoj
- **GitHub**: https://github.com/khoj-ai/khoj
- **Stars**: 25k+
- **技术栈**: Python + TypeScript
- **功能**: 本地 AI 第二大脑，支持多种数据源
- **集成状态**: ⚠️ 代码完整但已迁移到 Mastra
- **参考价值**:
  - 多数据源集成（文件、笔记、网页）
  - 定时任务和 AI 总结
  - 本地部署方案
  - Agent 系统设计
  - 对话和搜索功能

#### mem0
- **GitHub**: https://github.com/mem0ai/mem0
- **Stars**: 24k+
- **技术栈**: Python
- **功能**: AI Agent 通用记忆层
- **集成状态**: ✅ 架构参考，已实现三层记忆系统
- **参考价值**:
  - 三层记忆架构（Resource → Item → Category）
  - 记忆提取和组织
  - RAG 和 LLM 检索方式

### 📝 笔记与任务

#### Blinko
- **GitHub**: https://github.com/blinkospace/blinko
- **Stars**: 4k+
- **技术栈**: TypeScript + React
- **功能**: 闪念笔记，AI 增强，轻量级
- **集成状态**: ✅ 核心平台，深度集成
- **参考价值**:
  - 快速输入 UX 设计
  - AI 增强笔记
  - 标签和分类系统
  - 任务管理功能

### 🌐 截图与翻译

#### Pot
- **GitHub**: https://github.com/pot-app/pot-desktop
- **Stars**: 12k+
- **技术栈**: Rust + Tauri
- **功能**: 划词翻译，OCR，多引擎
- **集成状态**: ✅ 功能参考，已实现
- **参考价值**:
  - Tauri 截图实现
  - 区域截图选择
  - OCR 集成方式
  - 划词翻译的系统级 hook

### 📁 文件管理

#### Paperless-ngx
- **GitHub**: https://github.com/paperless-ngx/paperless-ngx
- **Stars**: 25k+
- **技术栈**: Python + Django
- **功能**: 文档 OCR、自动分类、全文搜索
- **集成状态**: ✅ 架构参考，已实现 PostgreSQL 文件服务
- **参考价值**:
  - 文档 OCR 流水线
  - 自动分类算法
  - 全文索引策略
  - 标签和分类系统

### 📂 智能整理

#### LlamaFS
- **GitHub**: https://github.com/iyaja/llama-fs
- **Stars**: 5k+
- **技术栈**: Python
- **功能**: AI 驱动的文件整理
- **集成状态**: ✅ 架构参考，已实现 Echo Janitor
- **参考价值**:
  - 文件夹监听

  - 语义重命名

### 3. 技术选型的演进与教训

**演进历程**:
- v2.0: SeekDB (向量数据库) + Khoj (AI 知识库)
- v3.0: PostgreSQL + SeekDB (双数据库) + Khoj
- v3.1: PostgreSQL + pgvector (单数据库) + Khoj
- v3.2: PostgreSQL + pgvector + Mastra (AI 服务统一)

**教训**:
1. **SeekDB 选型失败**: 新项目（2025年11月发布），稳定性不足
2. **Khoj 集成投入过多**: 代码完整但最终迁移到 Mastra
3. **技术栈不一致**: Python (Khoj) + TypeScript (Blinko) 增加维护成本

**建议**:
- 在早期做更充分的技术调研
- 优先选择成熟、稳定的开源项目
- 保持技术栈一致性

```
评价：
⚠️ 技术选型变化频繁，导致代码重构
✅ 最终收敛到单一技术栈 (TypeScript)
```
