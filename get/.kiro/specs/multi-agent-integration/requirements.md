# Requirements: Multi-Agent System Deep Integration

## Overview

将已实现的多 Agent 投资分析系统深度集成到现有的 UI 组件和服务中，包括 RiskCenter、DecisionCenter Chat、Daily Briefing 和 Voice Service。

## Glossary

- **Multi-Agent System**: 多专家协作分析系统，包含 5 个专业 Agent
- **Agent Orchestrator**: Agent 编排器，协调多个专业 Agent 的执行
- **useMultiAgent Hook**: React Hook，用于在 UI 组件中使用多 Agent 系统
- **Agent Alert**: Agent 触发的风险警报

## Background

### 已实现的 Multi-Agent System

- **5 个专业 Agent**: Position Analyst, Risk Analyst, Market Analyst, Web Surfer, Advisor
- **4 种编排模式**: sequential, selector, handoff, respond_directly
- **增强功能**: Personality System, Memory System, Extended Thinking, AI-Triggered Alerts
- **数据源**: Serper (新闻), SEC (财报), Jina (网页内容)
- **入口**: `client/src/services/agents/multiAgentService.ts`

## Requirements

### Requirement 1: RiskCenter AI Panel Integration

**User Story:** As a risk manager, I want the RiskCenter AI panel to use the multi-agent system, so that I get comprehensive analysis from multiple specialized agents.

#### Acceptance Criteria

1. WHEN user clicks "开始分析", THE RiskCenter SHALL call useMultiAgent.analyze()
2. WHILE analysis is running, THE RiskCenter SHALL display progress for each Agent (Position → Risk → Market → Advisor)
3. WHEN analysis completes, THE RiskCenter SHALL show each Agent's summary in expandable sections
4. WHEN an Agent triggers an alert, THE RiskCenter SHALL display it in the risk log with Agent name and reasoning
5. WHEN user asks follow-up questions, THE useMultiAgent SHALL use respond_directly mode for fast response

### Requirement 2: DecisionCenter Chat Integration

**User Story:** As an investor, I want the chat to intelligently route my questions to the appropriate analysis mode, so that I get fast answers for simple questions and deep analysis for complex ones.

#### Acceptance Criteria

1. WHEN user asks a simple question (confidence > 0.8), THE Chat SHALL use respond_directly mode and respond quickly
2. WHEN user asks a complex analysis question (confidence < 0.8), THE Chat SHALL use sequential mode for deep analysis
3. WHILE multi-agent analysis runs, THE Chat SHALL show Agent thinking process in a collapsible section
4. THE Chat SHALL preserve existing RAG citation functionality
5. THE Chat SHALL allow users to manually select analysis depth

### Requirement 3: Daily Briefing Integration

**User Story:** As an investor, I want daily insights generated by multiple specialized agents, so that I get comprehensive analysis covering positions, risks, and market conditions.

#### Acceptance Criteria

1. WHEN generating daily insight, THE aiService SHALL use Position_Analyst for position changes
2. WHEN generating daily insight, THE aiService SHALL use Risk_Analyst for risk assessment
3. WHEN generating daily insight, THE aiService SHALL use Market_Analyst for market news
4. WHEN generating daily insight, THE aiService SHALL use Advisor for final recommendations
5. THE Daily_Briefing SHALL display each Agent's key findings with expandable details

### Requirement 4: Voice Service Integration

**User Story:** As a user, I want voice interactions to include agent analysis context, so that voice responses are informed by the latest multi-agent insights.

#### Acceptance Criteria

1. THE Voice_Service SHALL fetch latest Agent analysis results as context
2. WHEN user says "帮我分析风险", THE Voice_Service SHALL trigger a new multi-agent analysis
3. THE Voice_Service SHALL include Agent key insights in voice responses
4. THE Voice_Service SHALL cache Agent analysis results for 5 minutes

### Requirement 5: AgentDemo Page Enhancement

**User Story:** As a developer, I want a comprehensive demo page to test and showcase all multi-agent features.

#### Acceptance Criteria

1. THE AgentDemo SHALL support switching between all 4 orchestration modes
2. THE AgentDemo SHALL visualize Agent execution flow
3. THE AgentDemo SHALL display Memory and Alert status
4. THE AgentDemo SHALL support custom Personality configuration
5. THE AgentDemo SHALL show Agent handoff messages

### Requirement 6: Performance Requirements

**User Story:** As a user, I want fast and responsive interactions, so that the system feels snappy.

#### Acceptance Criteria

1. THE respond_directly mode SHALL complete within 3 seconds
2. THE sequential mode SHALL complete within 30 seconds
3. WHILE analysis runs, THE system SHALL provide progress updates at least every 3 seconds
4. THE system SHALL cache Agent analysis results for 5 minutes

### Requirement 7: Error Handling and Fallback

**User Story:** As a user, I want the system to gracefully handle failures, so that I always get some useful response.

#### Acceptance Criteria

1. IF a single Agent fails, THEN THE Agent_Orchestrator SHALL continue with remaining Agents
2. IF multi-agent analysis fails, THEN THE system SHALL fallback to legacy implementation
3. THE system SHALL display friendly error messages with retry options
4. THE system SHALL log all errors for debugging
