# 先调研后执行原则

## 核心规则

**禁止在不确定的情况下直接执行命令或编写代码。**

## 执行流程

```
收到任务 → 搜索资料/文档 → 确认方案 → 执行
              ↓
          不确定 → 继续搜索或询问用户
```

## 具体要求

### 1. 部署/运维任务
- 先搜索官方文档，确认正确的命令和步骤
- 查看项目中是否有现成的部署脚本或配置
- 不要凭记忆执行可能过时的命令

### 2. 新技术/工具
- 先用 `deepwiki` 或 `context7` 查文档
- 确认版本兼容性
- 找到可验证的示例

### 3. 复杂操作
- 分步骤执行，每步验证
- 出错时先分析原因，不要盲目重试
- 超过 2 次失败，停下来重新调研

## 禁止行为

| ❌ 禁止 | ✅ 正确 |
|--------|--------|
| 凭记忆执行命令 | 先查文档确认 |
| 连续尝试不同方案 | 调研后选择最佳方案 |
| 超时后继续等待 | 分析原因，换方案 |
| 假设环境已配置好 | 先检查前置条件 |

## 调研资源优先级

1. 项目内现有配置/脚本
2. 官方文档 (GCP, Vercel, etc.)
3. GitHub 上的成熟开源方案
4. 技术博客/教程
