# QA 验证规则

## 最高指令

**禁止未经验证就汇报"完成"。**

## 执行流程

```
编码 → 运行 → 验证 → 通过? → 汇报
                ↓
              失败 → 静默修复 → 重新运行
```

### 验证要求

1. **检查日志**：无 Error、无 Warning
2. **检查结果**：输出符合预期
3. **自问**：交给用户会不会被骂？

### 前端功能验证

优先级：
1. **Vitest 单元测试** - 组件逻辑
2. **手动验证** - 启动 dev server 让用户确认
3. **Playwright E2E** - 复杂交互流程（需启用 playwright MCP）

## 汇报格式

只有 100% 确认通过后：

```
✅ [Verified] 任务完成，已通过测试。
```

## 禁止行为

| ❌ 禁止 | ✅ 正确 |
|--------|--------|
| 假设运行成功 | 检查实际输出 |
| 报错后汇报完成 | 静默修复后重试 |
| 跳过测试 | 运行相关测试 |
| 发送半成品 | 反复修复直到正确 |
