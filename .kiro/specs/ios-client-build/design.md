# Design Document: iOS Client Build

## Overview

本设计文档描述了 Echo iOS 客户端的构建和分发架构。采用 Tauri 2.x 框架构建跨平台应用，通过免费 Apple ID 实现本地开发测试，通过 AltStore 实现长期分发。

## Components and Interfaces

### 1. Build System

负责编译 Tauri iOS 应用。

```typescript
interface BuildConfig {
  mode: 'debug' | 'release';
  target: 'aarch64-apple-ios' | 'aarch64-apple-ios-sim';
  bundleIdentifier: string;
  version: string;
  developmentTeam?: string;
}

interface BuildResult {
  success: boolean;
  appPath?: string;
  ipaPath?: string;
  errors?: string[];
}
```

### 2. Signing System

管理 iOS 代码签名。

```typescript
interface SigningConfig {
  appleId: string;
  teamId?: string;  // 免费账号自动生成
  signingIdentity: 'Apple Development' | 'iPhone Distribution';
  provisioningProfile?: string;
}

interface SigningResult {
  signed: boolean;
  expiresAt: Date;  // 免费账号 7 天后过期
  certificate: string;
}
```

### 3. Distribution System

管理 AltStore 分发。

```typescript
interface AltStoreSource {
  name: string;
  identifier: string;
  apps: AltStoreApp[];
}

interface AltStoreApp {
  name: string;
  bundleIdentifier: string;
  developerName: string;
  version: string;
  versionDate: string;
  versionDescription: string;
  downloadURL: string;
  localizedDescription: string;
  iconURL: string;
  size: number;
}
```

## Correctness Properties

*A property is a characteristic or behavior that should hold true across all valid executions of a system—essentially, a formal statement about what the system should do. Properties serve as the bridge between human-readable specifications and machine-verifiable correctness guarantees.*

### Property 1: IPA File Structure Integrity

*For any* valid IPA file generated by the build system, unzipping it SHALL reveal a Payload directory containing an .app bundle with:
- Info.plist file
- Executable binary
- Required asset catalogs

**Validates: Requirements 4.2**

### Property 2: AltStore Source JSON Schema Compliance

*For any* AltStore source JSON generated by the distribution system, it SHALL contain:
- `name` (non-empty string)
- `identifier` (valid bundle identifier format)
- `apps` array with at least one app entry
- Each app entry SHALL have: `name`, `bundleIdentifier`, `version`, `downloadURL`

**Validates: Requirements 5.2**

## Error Handling

### Build Errors

| Error | Cause | Resolution |
|-------|-------|------------|
| `Xcode not found` | Xcode 未安装 | 安装 Xcode 或 Command Line Tools |
| `iOS SDK not found` | iOS SDK 缺失 | 打开 Xcode 完成初始化 |
| `Rust target not installed` | 缺少 iOS target | `rustup target add aarch64-apple-ios` |
| `CocoaPods not found` | CocoaPods 未安装 | `brew install cocoapods` |

### Signing Errors

| Error | Cause | Resolution |
|-------|-------|------------|
| `No signing certificate` | 未配置 Apple ID | 在 Xcode 中登录 Apple ID |
| `Certificate expired` | 7 天有效期已过 | 重新签名应用 |
| `Device not trusted` | 设备未信任证书 | 设置 → 通用 → VPN与设备管理 → 信任 |

### Deployment Errors

| Error | Cause | Resolution |
|-------|-------|------------|
| `Device not found` | USB 未连接或驱动问题 | 检查连接，重启设备 |
| `Developer Mode disabled` | 开发者模式未开启 | 设置 → 隐私与安全 → 开发者模式 |

## Testing Strategy

### Unit Tests

由于 iOS 构建涉及大量系统依赖和物理设备，单元测试主要覆盖：

1. **配置文件验证** - 验证 tauri.ios.conf.json 格式正确
2. **AltStore JSON 生成** - 验证生成的 source.json 符合 AltStore 规范
3. **构建脚本逻辑** - 验证脚本参数解析和错误处理

### Property-Based Tests

使用 fast-check 进行属性测试：

1. **Property 1**: IPA 文件结构完整性
   - 生成随机的 app 配置
   - 验证生成的 IPA 包含所有必需文件

2. **Property 2**: AltStore JSON 模式合规性
   - 生成随机的 app 元数据
   - 验证生成的 JSON 符合 AltStore 规范

### Integration Tests

需要在 macOS 环境下手动执行：

1. 完整构建流程测试
2. 设备部署测试
3. AltStore 安装测试

### Test Configuration

```typescript
// vitest.config.ts
export default {
  test: {
    include: ['**/*.test.ts'],
    coverage: {
      reporter: ['text', 'json', 'html']
    }
  }
}
```

Property-based tests 配置至少 100 次迭代，使用 fast-check 库。
